# Executive Summary

交付 PC-080..PC-172 共 93 条运营后台范围：17 个业务域可导航、可筛选的配置驱动功能台账，资金链路专用工作台，以及逐条可解析追踪。24 条 UNCONFIRMED 保留原始口径，UI 与 service 均禁止真实动作。

实现保留现有 React/TypeScript/Ant Design/React Router 页面；新增页面只经 `requirementLedgerService` 读取 Mock。金额与比例输入分别强制整数分和整数基点。fresh 全量测试 11 files/41 tests、typecheck、build 均通过。

## 交付范围说明

本次范围严格来自 `experiment/requirements.pc.json`，起点是 PC-080，终点是 PC-172。实现没有读取其他实验 workspace，也没有借用 comparator、reference 或原业务项目。registry 初始化时保留来源文件中的需求编号、Excel 行号、业务域、模块、扩写说明、来源哈希和未确认标记，再补充后台路由与页面类型。这样页面展示的数据与追踪文档共享同一需求事实，避免手工维护两份清单造成漂移。

17 个业务域全部出现在左侧“PC 功能台账（17域）”菜单下。运营人员既可以进入“全部 93 条”，也可以直接选择内容运营、用户管理、发票抽奖、分类信息、商家管理、电商管理、积分管理、票券管理、积分权益、活动报名、生活缴费管理、小程序管理、焦点图、平台协议与常见问题、财务管理、系统管理和到家服务管理。台账提供关键词、业务域和确认状态筛选，详情抽屉保留完整来源说明与哈希。

资金相关条目不只显示在通用表格中。registry 根据支付、退款、分账、结算、对账、资金、金额、费率、佣金、提现和充值等来源语义归入资金工作台。工作台明确展示幂等键、业务状态、操作审计、异常原因和对账处理这五类治理信息，并继续保留项目已有的支付、退款、分账、结算、资金池与对账专页，不用新页面替代已有能力。

## 完成判定

完成判定不是“页面能编译”这一条。registry 测试证明 93 个 ID 连续且唯一、业务域恰为 17、UNCONFIRMED 恰为 24；service 测试证明禁用动作无法绕过 UI、确认条目使用相同幂等键不会重复审计、非法小数金额和越界比例会被拒绝。全量测试还覆盖项目原有的资金池、分账、结算资格、积分发放、隐私脱敏和 V0.3 页面合同。最终追踪 JSON 再独立检查数量、唯一性、12 个合同字段和 locator 路径存在性。
